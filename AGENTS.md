# AGENTS.md

Personal website built with SvelteKit 3 (Svelte 5 runes), Tailwind CSS 4, and
mdsvex, deployed to Cloudflare with `@sveltejs/adapter-cloudflare`.

## Setup and commands

The dev shell comes from `flake.nix` via direnv (`.envrc`). The Node major
version lives in `.node-version`, which the flake and Cloudflare's build both
read; keep `engines.node` in `package.json` in sync with it.

- `npm run dev`: start the Vite dev server on port 5173
- `npm run build`: production build, which prerenders the site
- `npm run check`: `svelte-kit sync` and `svelte-check`
- `npm run lint`: Prettier check and ESLint
- `npm run format`: format everything with Prettier

Run `npm run lint` and `npm run check` before calling a change done. There are
no tests.

## Layout

- `src/routes/`: pages; `+layout.svelte` holds the header, footer, and `<head>`
  tags
- `src/routes/(pgp)/`: the PGP page (`index.svx`) and the HKP key routes
- `src/lib/index.ts`: shared helpers (`formatTitle`, `ErrorMessage`, ...) and
  re-exports of `src/lib/posts`
- `src/lib/posts/`: notes as Markdown files in `YYYY/` folders, plus `tags.ts`,
  which defines `postTags`, and `index.ts`, which loads post modules
- `src/lib/components/`: shared components, imported as `#components/*`
- `src/lib/components/Grain.svelte` and `src/lib/assets/shaders/`: the animated
  WebGL 2 background, adapted from Paper Shaders' grain gradient (Apache 2.0,
  keep the credit comments). `grain.glsl` renders the static grain into a
  texture once per canvas size, and `lava-lamp.glsl` draws the moving blobs over
  it each frame, in theme colors read from the `--color-*` variables
- `src/params.ts`: route param matchers for posts and tags. SvelteKit imports it
  with plain Node at build time, so it can't import anything that needs Vite
  (`import.meta.glob`, enums, `#lib` itself)
- `vite.config.ts`: Vite and SvelteKit config (there is no `svelte.config.js`)
- `_headers`: Cloudflare response headers for static and prerendered files;
  `src/hooks.server.ts` sets the same ones on worker responses
- `src/app.css`: Tailwind config (`@theme` color palette and fonts, typography
  (prose) colors) and global base styles
- `src/lib/assets/fonts/` and `src/lib/assets/css/curlio.css`: Curlio WOFF2s and
  a `@font-face` for each one, imported by `app.css`. Both are generated by
  `nix run .#update-fonts` from the dotfiles curlio flake
  (`nix flake update curlio` first to pick up font changes); don't edit them by
  hand
- Formatting is Prettier: no semicolons, single quotes, and `proseWrap: always`
  (Markdown wraps at 80 columns). `prettier-plugin-tailwindcss` sorts class
  lists, so don't hand-order them.
- Internal links use `resolve()` from `$app/paths`, and external links need
  `rel="external"`. ESLint's `svelte/no-navigation-without-resolve` enforces
  both.
- Icons are Tabler icons imported from `~icons/tabler/<name>` (unplugin-icons).
  Decorative icons get `aria-hidden`.
- All `<a>` elements are underlined by the base style in `app.css`. To keep an
  icon out of the underline, put the label in a `<span>` inside a flex `<a>`.
- Theme follows `prefers-color-scheme` (Tailwind's default `dark:` variant);
  there is no theme toggle. Every color needs both variants: `light-*` by
  default and the plain name under `dark:`, e.g.
  `text-light-orange dark:text-orange`. Write class names out in full so
  Tailwind can find them.
- CSS files other than `app.css` that use `@apply` or theme values need
  `@reference '<path>/app.css';` at the top (see
  `src/lib/assets/css/shiki.css`).
- Check text color contrast against both backgrounds (WCAG AA, 4.5:1 for normal
  text) when picking palette colors.
- `src/index.d.ts` stubs the `mdsvex` module types on purpose: mdsvex's bundled
  types are too old for the current remark/rehype plugins. Don't remove it.
- A content security policy is set in `vite.config.ts`. Inline scripts and
  third-party origins are blocked unless added there.
